# 4DoF定位安全后续代办

本文件记录当前版本明确尚未解决、不得用调大阈值掩盖的问题。

## P0：RTK/LIO冲突与源切换台阶

- 增加独立的同时间源切换门，不能复用最终动态连续性门：
  - 比较候选RTK与 `T_committed(LIO(t))`；
  - 建议预警阈值从0.20–0.30m现场标定，必须严格小于锁定创新拒绝阈值；
  - 超限进入 `SOURCE_CONFLICT`，保持当前连续源并降速/停车，不能硬切；
  - 解决当前0.40m创新阈值与约0.45m/0.75m输出门之间可能放行约0.4m台阶的问题。

## P0：RTK与LIO慢慢分离

- 对同时间RTK−冻结LIO创新记录滑窗均值、方差、斜率和CUSUM。
- 设置正常、预警、冲突三级滞回，防止在单帧阈值附近抖动。
- 在达到硬阈值前主动降速并保留诊断证据。
- 不能用同一拟合窗口的残差代替跨传感器趋势检测。

## P0：LIO长时漂移但RTK正确时的故障归因

- 接入LIO配准残差、退化方向、地图重定位置信度。
- 接入轮速/IMU短时运动一致性；只有RTK和LIO两个冲突源时不得宣称唯一归因。
- 建立显式状态：
  `LOCKED / RTK_DEGRADED / LIO_DEGRADED / SOURCE_CONFLICT`。
- 无法归因时停车，不默认把冻结LIO或RTK声明为真值。

## P1：受控完整4DoF重对齐

- 锁定状态下继续保持生产变换不可写。
- 在停车或受控低速条件进入 `REALIGN_PENDING`，使用独立shadow窗口估计新4DoF。
- 新变换必须经未参与拟合的留出观测、RTK真实质量、LIO健康和源切换连续性共同验证。
- 通过后原子切换完整 `theta/tx/ty/tz`，并同步重置规划/控制位置基准；失败则保持旧变换并停车。

## P1：上游硬件测量时间

- 在1ant端将 `gps_week/gps_millisecond`转换为与LIO一致的ROS时基。
- 处理闰秒、周跳、主机时钟同步和时间回退。
- 在完成统一时基前，4DoF不得自行猜测或伪造硬件测量时间戳。

## 验收要求

- 回放2026-09-10三个故障bag的派生场景，并注入缓慢RTK漂移、缓慢LIO漂移、
  单帧缺失、连续缺失、假固定和时间抖动。
- 所有源切换必须报告同时间位置/yaw差、选择原因及状态迁移。
- 不允许发布超过现场控制安全阈值的台阶；无法归因必须安全停车。
